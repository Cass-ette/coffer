# Coffer 设计文档（Spec）

日期：2026-09-15
状态：已与需求方逐节确认

## 1. 一句话定位

一个仅运行于 macOS 的本地密码与权限保险库：把网站账号、开发运维密钥、TOTP 验证码、敏感笔记，以及"我能访问哪些系统"这件事本身，收进一个 Touch ID 一按即开的加密库里。

## 2. 背景与核心痛点

需求方的真实痛点不是"没有地方存密码"，而是**遗忘**：手上有多个系统的访问权限（部分在局域网），时间一长记不清"我到底能进哪些系统、账号是什么、在内网还是公网"。现有钥匙串类工具以"自动填充"为中心，不擅长做**权限资产的检索与盘点**。

因此本产品的核心价值排序：

1. **检索优先**——全局模糊搜索 + 分组目录 + 标签体系，三种找回方式并存
2. **解锁零摩擦**——日常解锁 = 按一次指纹
3. **安全按业界默认值**——本地加密、自动锁定、剪贴板自清，不做过度设计

## 3. 需求清单（已确认）

| 项 | 决定 |
|---|---|
| 平台 | 仅 macOS（当前机器，macOS 26），无 iOS、无同步、无网络行为 |
| 存储内容 | 网站账号、访问权限记录、API key/token/数据库密码、SSH 私钥、TOTP 种子、敏感笔记（含证件照片附件） |
| 解锁 | Touch ID 为主，Mac 登录密码为系统级备选，主密码为最终兜底 |
| 检索 | 全局模糊搜索 + 一层平级分组 + 自由标签 |
| 形态 | 主窗口应用 + 全局快捷键呼出的浮动搜索面板 |
| UI | 现代原生、克制、拒绝模板味；深浅色跟随系统 |
| 导入 | 不做（全新录入） |
| 威胁模型 | 需求方明示"没想那么多"，按业界默认值设计（见 §5） |

## 4. 非目标（v1 明确不做）

- 浏览器自动填充 / 浏览器扩展
- iOS / 多设备 / 云同步
- 数据导入器
- 密码生成器的复杂策略配置（仅保留一个合理的随机生成按钮）
- 密码健康审计、泄露检查
- 拼音搜索（条目直接用中文标题，输入法即可命中；拼音匹配留作未来项）

## 5. 安全模型

### 5.1 两层钥匙结构

```
vault.vault 文件（单文件，AES-256-GCM 加密的 JSON，原子写入）
     │
   DEK：随机 256 位数据密钥，仅存在于内存
     │
  ┌──┴────────────────────────────┬──────────────────────────┐
  │ 主密码路径                      │ 生物认证路径               │
  │ PBKDF2-SHA256(600k 迭代)       │ Keychain 条目              │
  │ 派生 KEK → 包装 DEK            │ ACL: Touch ID / Mac 密码   │
  │ （包装结果存 vault 文件内）      │ （DEK 明文永不出安全硬件）  │
  └───────────────────────────────┴──────────────────────────┘
```

- **首次启动**：设置主密码（二次确认）→ 生成 DEK → 加密空 vault；同时把 DEK 写入 Keychain（绑定生物认证 ACL），此后日常解锁只需指纹
- **Keychain 条目**：`kSecClassGenericPassword`，`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`，访问控制用 userPresence 语义（Touch ID 优先，Mac 登录密码为系统级备选）；本设备、本用户、不可迁移
- **App 永远接触不到指纹数据**，验证发生在 Secure Enclave；App 只拿到"放行/拒绝"
- **主密码是最终兜底**：生物认证全部不可用时（重启初期、硬件故障），输入主密码走 PBKDF2 路径解包 DEK
- 修改主密码 = 重新包装 DEK，数据不重加密

### 5.2 锁定策略

- 闲置自动锁定：默认 5 分钟，可配（1 / 5 / 15 / 不自动）
- 系统事件立即锁定（不依赖闲置计时）：睡眠、锁屏、切换用户、屏保启动
- 锁定 = 内存中 DEK 与所有解密数据清零（敏感字节用 `ContiguousArray<UInt8>` 持有，尽力覆写；Swift String 无法保证清零，spec 如实承认这是 best-effort）

### 5.3 剪贴板保护

- 复制敏感字段后 45 秒自动清空剪贴板（可配 30 / 45 / 60 / 不清）
- 锁定不取消清剪贴板计时，防止"库锁了、密码还在剪贴板躺着"的缝

### 5.4 PBKDF2 说明

CryptoKit 不提供 PBKDF2，使用系统自带 CommonCrypto 的 `CCKeyDerivationPBKDF`（SHA-256，600,000 迭代，随机 16 字节盐）。仍是零第三方依赖。高迭代本身就是防离线爆破的手段，主密码输错不做惩罚性锁死。

## 6. 数据模型

### 6.1 统一 Entry

六种类型共用一个 Entry 模型（跨类型全局搜索的前提）：

```swift
struct Entry: Codable, Identifiable {
    let id: UUID
    var type: EntryType            // login / access / apiKey / sshKey / totp / secureNote
    var title: String
    var subtitle: String           // 列表第二行，如用户名、主机名
    var groupID: UUID?             // 所属分组（单选）
    var tags: [String]
    var isFavorite: Bool
    var permissionNote: String     // "我的权限"备注，所有类型都有
    var customFields: [CustomField] // 名值对，可标记为敏感
    var createdAt / updatedAt: Date
    // 类型特有载荷放各类型的 struct，经 Codable 多态编码
}
```

| 类型 | 用途 | 特有字段 |
|---|---|---|
| `login` | 网站账号 | username、password、多 URL（域名与内网 IP 可并存） |
| `access` | **纯权限记录**（无密码也值得记） | 系统地址（多个）、登录方式（SSO/密码/免登）、网络位置（内网/公网）、角色说明 |
| `apiKey` | API key、token、数据库密码 | 服务商、secret、环境前缀 |
| `sshKey` | SSH 私钥 | 主机、用户、私钥文本（公钥可由私钥推导或单独存） |
| `totp` | 2FA 动态码 | 种子（支持粘贴 `otpauth://` URI 自动解析）、算法（SHA-1 默认）、位数（6 默认）、周期（30s 默认） |
| `secureNote` | 证件、恢复码、助记词 | 富文本正文、加密附件 |

### 6.2 分组与标签

- 分组：一层平级，预置"内网系统 / 校内服务 / 开发密钥 / 个人"四个可改名可删，条目至多属一个分组
- 标签：自由字符串，无层级，侧边栏按标签聚合
- 附件（仅 secureNote）：单张 ≤ 2MB，录入时拦截超限；附件随 vault 一起加密

### 6.3 vault 文件格式

```json
{
  "format": "coffer-vault", "version": 1,
  "kdf": { "algo": "PBKDF2-SHA256", "iterations": 600000, "salt": "…" },
  "wrappedDEK": "…",          // 主密码路径的包装结果
  "nonce": "…",                // AES-256-GCM 96-bit nonce，每次保存随机
  "ciphertext": "…",          // AES-256-GCM(ciphertext + tag)
  "updatedAt": "…"
}
```

- 明文 payload 是一个 JSON（entries + groups + settings + schemaVersion），整库加密
- 位置：`~/Library/Application Support/Coffer/vault.vault`
- 保存 = 写临时文件 → `rename` 原子替换；每次成功保存前，将旧文件轮换进 `vault.bak1~3`
- 版本迁移：未来 format version 变更时按 version 逐级升级，v1 只需读取自己

## 7. 检索设计

- 解锁后全量条目进内存索引，搜索无 I/O
- 匹配：模糊子序列（连续命中加权）+ 子串命中，匹配范围与权重：标题 > 标签 > URL/地址 > subtitle > 权限备注
- 分组目录与标签聚合与搜索正交组合（在"内网系统"分组内再搜）
- 全局浮窗与主窗口共用同一搜索实现

## 8. UI 设计

### 8.1 审美方向

- 顺系统而生：毛玻璃侧边栏、系统材质、SF Symbols、深浅色跟随；设计感来自克制——单一强调色、严格字阶与留白，拒绝渐变大卡片与装饰性元素堆砌
- 字体二分：界面 SF Pro；密钥、验证码、命令等"机器串"一律 SF Mono 等宽，一眼可辨"这是要复制的"
- 锁定页是设计展示位：图标 + 指纹按钮 + 主密码入口，极简

### 8.2 主窗口（三栏）

```
┌─────────────┬──────────────────┬──────────────────────┐
│ 🔍 搜索      │ APT 预约系统   ⭐  │  详情：字段行 + 操作    │
│ ⭐ 收藏      │ …列表实时过滤…    │  密码默认打码可显形     │
│ ▸ 分组 ×N    │                  │  TOTP 大号码+环形倒计时 │
│ 标签: #内网… │        ＋ 新建    │  #标签 / 编辑 / 删除   │
└─────────────┴──────────────────┴──────────────────────┘
```

### 8.3 全局搜索浮窗

- 默认快捷键 `⌥Space`，可在设置中修改；注册冲突（如 Raycast 占用）时提示用户换键
- 居中 NSPanel + 毛玻璃；锁定状态下呼出 → 先指纹 → 直接进入搜索
- 键盘闭环：↑↓ 选择、↵ 复制用户名（或该类型主字段）、Tab 循环复制目标（密码/验证码/地址）、⌘↵ 打开 URL、Esc 关闭；复制完成自动关闭浮窗并启动剪贴板清空计时
- TOTP 结果行内直接显示实时验证码与剩余秒数

### 8.4 App 图标（Logo）

- 自绘几何标志：以"保险箱/钥匙孔"为核心母题，单一强调色 + 深色底，简洁锐利，拒绝拟物渐变和 AI 生成感
- 交付物：SVG 源文件 + 1024×1024 PNG 进 Asset Catalog（AppIcon），项目仓库 `assets/brand/` 存源文件

## 9. 错误处理

| 场景 | 行为 |
|---|---|
| 指纹取消/失败 | 锁定页常驻主密码入口 |
| 主密码错误 | 即时提示错误；PBKDF2 高迭代即防爆破，不惩罚性锁死 |
| vault 校验失败/损坏 | 明确报错，引导从 `vault.bak1~3` 恢复（设置内提供"从备份恢复"入口） |
| 磁盘写入失败 | 原子写保证旧文件不损坏；报错并保留内存态不丢编辑 |
| 附件超 2MB | 录入时拦截提示 |
| 快捷键注册冲突 | 启动时检测，设置页提示换键 |
| 保存时程序崩溃 | 最多丢失自上次自动保存以来的改动；锁定/退出前强制保存 |

## 10. 测试策略

- **单元测试（XCTest）**：加解密 roundtrip；PBKDF2 与 TOTP 使用 RFC 6070 / RFC 6238 官方测试向量；模糊搜索排序用例（标题命中 > 标签 > URL > 备注；连续子序列 > 离散）；备份轮换与损坏恢复流程；vault schema 编解码
- **必须真机手动验证**（模拟器无 Touch ID）：指纹解锁全流程、Mac 密码备选路径、主密码兜底路径、全局热键、睡眠/锁屏联动锁定、剪贴板自动清空——交付时提供逐项验收清单
- **UI 冒烟**：主窗口三栏渲染、新建/编辑/删除条目、浮窗呼出与键盘导航

## 12. 成功标准

1. 日常场景：任意应用中 `⌥Space` → 指纹 → 敲两三个字 → 复制到密码，全程 ≤ 5 秒
2. "我又能访问哪些内网系统来着？"——搜索或按"内网系统"分组浏览，30 秒内得到答案
3. 电脑被抱走拔盘：vault 文件单独拿到手无法解出任何明文
4. 视觉上"不像 AI 生成的应用"：通过需求方肉眼验收
