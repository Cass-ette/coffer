## 先按需求选择

| 你的需求 | 优先核对的方案 | 做决定前看什么 |
|---|---|---|
| 偶尔转一笔，普通地址已有 TRX | 在普通转账页比较“直接用 TRX”和“按次租能量” | 比较两种方案的**预计总支出**，不是只看租金；急用时也要考虑资源到账等待 |
| 普通地址已有足够能量、带宽 | “直接用 TRX”入口会先抵扣现有资源 | 这个按钮不等于一定烧 TRX；资源足够时，相应资源费用可以为零 |
| 长期规律转账，愿意占用 TRX 本金 | 评估自己质押后使用资源 | 看每日资源消耗、恢复速度、资金占用和币价风险；Coffer 暂无质押/解押界面 |
| 不想持有 TRX，准备直接在独立地址收 USDT | 了解 GasFree 后再选择其收款地址 | 首次激活费、每笔服务费、凭证要求、服务可用性，以及付款方能否向合约地址转账 |
| USDT 已在普通地址，只为这一笔改用 GasFree | 先算迁移成本，再比较 | 普通地址转入 GasFree 本身要付费；迁移费加首次费用可能抵消节省 |
| 只想收款或观察余额，不在本机转出 | 普通收款地址；也可仅导入地址 | 仅地址条目不能签名；以后转出仍需控制该地址的凭证与相应费用 |

**没有固定的“自己质押 < 租能量 < 烧 TRX < GasFree”价格排序。** 前三项主要区别是能量从哪里来；GasFree 则是服务商代为提交交易、用户用 USDT 结算费用。已有资源、租金、网络费、首次费用及是否需要搬币，都会改变结果。[1] [2] [5]

## 几种方式的区别与成本

### 普通地址直接付费：简单，不一定最贵

入口：钱包详情 → **转账** → 查看报价 → **直接用 TRX**。

普通 USDT 合约转账需要能量和带宽。Coffer 会查询本地址现有资源，优先抵扣，再估算不足部分要燃烧的 TRX。因此，“直接用 TRX”也能使用已经取得的质押或委托资源。[1] [2]

- **优点**：无需再购买一份资源，不增加租赁付款步骤；已有资源时尤其方便。
- **代价**：资源不足时按链上费率付费；实际执行失败也可能收费。
- **安全边界**：不额外依赖租赁商或 GasFree 服务商，但仍依赖本机密钥安全、节点可用性和 USDT 合约执行。

Coffer 的预计支出可理解为：

```text
直接方案预计 TRX = 当前能量缺口 × 当前能量单价 + 当前带宽不足产生的费用
```

带宽按链上规则处理，并非总能简单只付“超出的几个字节”。能量消耗与合约执行有关，**转账金额小不保证手续费低**；动态能量和合约状态也可能使前后两笔费用不同。使用本次模拟和当前参数，不套用固定的“每笔需要多少 TRX”。[1] [4]

### TronSave 按次租能量：少占本金，多一个服务环节

入口：普通转账页有可成交报价时，选择 **按次租能量**。

Coffer 当前接入 TronSave 的**一小时、按订单付费**产品，按本次缺口询价；先提交本地签名的 TRX 租赁付款，查询付款成功且本地址能量足够后，再转出 USDT。不要求用户先给平台充值余额。[6]

```text
租赁方案预计 TRX = 固定租金 + 租赁付款网络费 + USDT 转账网络费
```

报价页还会给出按当前费率和资源计算的执行上限，覆盖执行余量可能引起的额外扣费；它不是预扣金额，也不是资源及费率变化后的永久价格承诺。

- **什么时候可能便宜**：能量缺口明显，且租金加两笔交易费用仍低于直接方案。
- **什么时候未必划算**：缺口很小、原有资源已足够、租金上涨，或额外付款使可用带宽耗尽。
- **代价**：需要等订单和资源；报价可能过期或不可成交；租赁按订单收费，未用完不承诺退款。
- **安全边界**：租赁商收到的是已签名的特定 TRX 付款，不是私钥。但钱付出后仍有交付延迟、订单争议和服务不可用风险；本地校验不能消除这些风险。

**一小时是本订单的使用期限，不是无限转账额度，也不是 Coffer 的自动续费订阅。** 不要因为订单到期或界面超时，就立即重复购买。租赁市场规则与产品可能变化，具体按当前报价核对。[6]

### 自己质押：资源可恢复，但资金和管理成本不能忽略

TRON 质押可取得资源，资源消耗后会在约 24 小时内逐步恢复，恢复足够就能继续使用；用掉的是资源额度，不是每次都销毁质押本金。资源额度有上限，不能无限囤积。[1] [3]

**Coffer 能查询、抵扣本地址已有的可用资源，但当前没有质押、解押、投票、委托或自动补仓入口。** 如需获取这些资源，应另行核对支持相应操作的钱包及官方说明，不能把本指南当作 Coffer 已提供这些操作。

- **可能适合**：长期、规律地转账，已有持有 TRX 的需求，且资源利用率足够高。
- **未必适合**：偶发转账、需要随时动用本金，或只为了少量手续费临时买入大笔 TRX。
- **成本怎么比**：看一段时间内避免的燃烧费用或租金，是否值得承担资金占用、价格变化和管理成本。不能因为某笔没有扣 TRX 就断言总成本为零。
- **本金流动性**：Stake 2.0 解押后有链上规定的提现等待期，不能当作随时可用的余额；等待参数及资源额度以当前链上规则为准。[3]

短时间连发多笔仍可能把资源耗尽。“规律、消耗量与恢复速度匹配”比“每笔金额小”更有参考价值。

### GasFree：用 USDT 付手续费，使用独立地址

入口：设置 → 验证 GasFree API Key / API Secret → 钱包详情 → **GasFree · 用 USDT 付手续费**。

GasFree 使用由当前钱包密钥控制的**独立合约地址**。服务商提交交易、承担链上资源成本，再按协议收取 USDT；不是把普通地址里的 USDT 自动兑换为 TRX。普通地址和 GasFree 地址的余额不通用。[5]

```text
GasFree 首次转出总扣款 = 对方收到的 USDT + 首次激活费 + 本笔服务费
后续转出总扣款 = 对方收到的 USDT + 本笔服务费
```

- **优点**：GasFree 地址不必准备 TRX；适合希望直接收 USDT、再用 USDT 支付手续费的需求。
- **成本要点**：首次和后续费用分开看；从普通地址搬币过去的那笔费用另算。跨模式比较时，把 TRX 与 USDT 的手续费按同一时点参考价格换成同一单位，再比较。
- **安全边界**：新增合约、服务商和 API 凭证依赖；私钥留在本机不等于没有合约风险或服务中断风险。API Secret 应只保存在本机设置，不发聊天、不放仓库。
- **当前限制**：Coffer 需要用户自己的官方主网凭证；普通转账页只自动比较直接方案与 TronSave，不会自动把余额迁移至 GasFree。

GasFree 的费用取自服务端新报价，具体收费机制见官方说明；不要把示例价格或活动折扣当成永久费率。Coffer 中金额表示对方收到的金额，手续费另加，须留足可用 USDT。[5]

## 收款地址怎么选

| 收到哪里 | Coffer 当前支持的用途 | 收款前核对 |
|---|---|---|
| 普通钱包地址 | 显示 TRX / USDT 余额、收款二维码；有凭证时可按普通流程转出 USDT | 对方明确选择 **Tron / TRC-20**；以后转出要准备资源或 TRX |
| GasFree 独立地址 | 接收 Tron 主网 USDT，再按 GasFree 流程转出 | 从 GasFree 页面复制地址；核对付款平台是否允许向合约地址转账，并预留首次及后续费用 |
| 仅地址条目 | 观察余额、展示二维码和复制普通收款地址 | Coffer 没有签名凭证，不能从该条目转出；收款地址应确实由你或预期收款人控制 |

普通地址尚未激活 Tron 账户时也可能已经收到 USDT。Coffer 直接查询 USDT 合约余额；“收到了 USDT”不代表已经拥有足够资源或 TRX 来转出。

收款不需要收款人批准“支出 USDT”的授权。只分享对应的收款地址或二维码，核对完整地址和网络；不要提供助记词、私钥或主密码。链上手续费通常由发起方按其发送方式承担，交易所等付款平台还可能另收提现费。**不要向 GasFree 地址发送 Coffer 未支持的资产，也不要把其他网络上的 USDT 发到这两个 Tron 地址。**

## 安全边界与异常处理

所有模式都要先核对收款人、网络、金额和费用，再进行独立认证。Coffer 会在本机签名并核验待签交易/授权的重要字段；服务商报价更便宜不等于更安全，本地实现和自动测试也不是第三方安全审计。

| 情况 | 应怎么做 |
|---|---|
| “节点已受理，等待链上结果” | 表示提交阶段完成，尚未拿到成功回执；按哈希查询，等待结果 |
| 广播/租赁提交超时、响应丢失 | 先查询已有付款或交易，**不要立即重复发送或购买** |
| 租赁付款成功但资源不足 | 查订单和当前资源；需要再次支出时先重新估价、确认，不能当作未付款 |
| 链上执行失败 | 核对失败原因和实际费用；失败不保证网络费或已付租金退回 |
| GasFree 授权待确认 | 在 GasFree 页面查询原记录；缺 traceId 时按页面请求编号联系官方恢复，不能反复提交 |
| 记录损坏或付款保护未解除 | 保留记录并排查；不要删除 `wallet-transactions` / `gasfree-transfers` 来强行绕过保护 |

各服务可见公开地址、报价请求或签名后的交易/授权。签名后的授权本身也可能具备执行效力，不应对外分享。查询失败、匿名 TronGrid 限流和缓存余额不等于资产丢失；用当前回执核对，别仅凭界面等待或服务商“已受理”判断成功。

## 当前实现和验证范围

| 项目 | 截至 2026-11-14 的状态 |
|---|---|
| 普通收款、USDT 余额刷新 | 已有用户在场的真实入账确认 |
| TronSave 一小时租赁 → USDT 转出 → 实际费用回执 | 已有一次用户亲自认证的小额主网成功验收；不代表覆盖所有状态 |
| 仅直接付费的转出路径 | 有自动回归；尚未单独完成真实主网验收 |
| 已有质押/委托资源抵扣 | 有实现与自动回归；未完成专门的实网质押场景验收 |
| GasFree | 有自动回归；真实服务及主网转出验收仍待完成 |
| 中断恢复、目标系统兼容性、保险库冷备份恢复 | 仍有人工验收项，详见[钱包验收记录](superpowers/wallet-validation-2026-10-11.md) |

当前 Core 与本地 HTTP 集成测试共 187 项通过；仿真环境及其模型边界见[本地钱包环境](../integration/wallet/README.md)。模拟不能代替真实服务、合约和支持系统上的验收。Coffer 尚未提供人民币自动估算功能，本文也不承诺任何方案的固定人民币价格。
